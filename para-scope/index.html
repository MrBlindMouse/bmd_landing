para-scope

Event hub and operational dashboard

Self-hosted for personal or small-team infrastructure.

Sources in via webhooks or polls. Rules and actions update shared fields, notify you, forward HTTP, push to the browser, or add kanban cards — on Main and named pages for dashboards, a calendar week, or a board.

A focused companion — not Prometheus/Grafana or a workflow engine like n8n.

Features

Sources and pipeline

Webhook receivers with HMAC and provider helpers (Stripe, GitHub, Slack, Discord, PayPal) plus scheduled pollers for APIs, health checks, RSS, IMAP, ICS calendars, and more. Event types, rules with conditions, and ordered actions on each match.

Shared fields

Named logbook, value, text, toggle, and data fields feed widgets and actions from one SQLite-backed store — no separate metrics database to run.

Actions

Push field updates, forward HTTP, notify via ntfy / Gotify / Discord, send Web Push, add kanban cards, or run optional local scripts — credentials encrypted at rest.

Dashboard pages

Drag-and-drop GridStack layouts on Main and named dashboard pages: charts, clocks, status, notes, and templates bound to field slugs at display time.

Calendar and kanban

Read-only ICS week view and a Next / Doing / Done board. Focus modes from calendar categories can drive fields and cards; moving a card can emit pipeline events.

Ops and style

Live event tail on /events, self-metrics on /system, audit log, pipeline and user config, plus themes, fonts, and dashboard backgrounds.

About

para-scope is for people who want one private place to watch small infrastructure and side projects: see when a webhook fires, whether a poll succeeded, and what changed — then do something about it, without standing up Prometheus, Grafana, or a workflow engine.

It started as a personal ops board and event inbox. The idea is to keep signals, a bit of history, and the views you care about (status, charts, calendar, kanban) under your own login on your own machine — not as a hosted product and not as enterprise observability.

It is meant to be approachable for a single user and deep enough to grow with a small team, with clear extension points for new pollers and actions. Scope stays intentionally modest: a companion hub, not a replacement for dedicated monitoring or automation platforms.
