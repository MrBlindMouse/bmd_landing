Portico

SSH terminal sites in Go

A framework for interactive, multi-user experiences in the terminal.

You write scenes and actions in your own module; Portico serves SSH, routes input, runs sessions, and holds shared spaces. Starter plans via portico generate — guestbook, chat, forms, and more.

The framework repo, not a finished site — bring your own world.

Features

Scenes and actions

Declare components in Go: scenes render the terminal; actions return effects. The runtime dispatches input and applies state changes — session and space updates stay in one place.

Installation builder

Merge components into an installation, validate wiring, and serve with portico.Serve. Convention over configuration so a small main can grow into a full site.

Spaces and presence

Shared spaces for multi-user flows. Identity comes from SSH keys plus optional accounts, nicknames, and KV stores — not a bolt-on auth stack.

CLI for site authors

portico init scaffolds a module; generate copies starter plans you own and edit. Docs, wire helpers, inspect snapshots, and dev serve round out the loop.

Rendering and themes

Layout and theme helpers for readable terminal UI. Scenes draw; render stays ignorant of session internals so structure stays predictable.

Agent-friendly shape

Designed so humans steer and agents implement: recognizable package boundaries, plans as copy-paste starters, and invariants enforced by tests and arch checks.

About

Portico is for people who want SSH to be more than a shell — small social spaces, playful lobbies, or bespoke text UIs — without hand-rolling session plumbing every time.

It is opinionated about structure (scenes, actions, effects, installation) and deliberately open about what you build on top. Not a web framework, not a MUD engine, not mass-scale game infra — a porch you can extend into a site.

The repo ships the framework and embedded plans; your module is the product visitors ssh into.
